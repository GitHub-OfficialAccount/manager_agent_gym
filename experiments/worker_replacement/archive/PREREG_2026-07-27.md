## 1. Confirmatory hypotheses

**Primary — H1.** The quarantined interpreted belief (`arm3i_q`) closes a positive
fraction of the oracle gap relative to native silent, on the two primary endpoints (§3).

**Mechanism — H2.** Any H1 gain is attributable to **completion quarantine** iff
`arm3i_noq ≤ ledger < arm3i_q`. If interpretation-without-quarantine already captures
it, the completion-mechanism claim is not warranted.

**Ladder decomposition (secondary).** Paired differences for
`native→summary`, `summary→summary_log`, `summary_log→ledger`,
`ledger→arm3i_noq`, `arm3i_noq→arm3i_q`, `arm3i_q→arm3t`.

**Sign is not prejudged** where ARM3_SPEC §1 says so: `ledger→arm3i_noq` may be zero or
negative.

## 3. Endpoints

**Primary (behavioral):** post-evidence corrective-routing rate — fraction of the B/C
robust audits routed to a non-degraded worker (A is pre-evidence = irreducible signal
delay; excluded from the numerator). Compare semantic assignment mappings, not literal
timesteps.

**Primary (reward):** oracle-gap closure `(R_arm − R_native)/(R_full − R_native)`,
reported **alongside absolute R_check** (ratio is unstable at small denominator).

**Secondary:** ladder-contrast paired differences (§1); stated-vs-behavioral detection
dissociation via `shadow-probes-v1.1` at pre-B/pre-C (offline, never re-entering
execution); latencies (first visible fact / first accepted relation / first rendered
contradiction / first corrective action); false-positive fit-degradation and rerouting
under `control`/`fp_ctrl_q`; extractor calls/failures/retries/latency/tokens; realized
prompt sizes.

## 4. Analysis plan and decision rules

- Paired difference scores across the 5 seeds; **paired bootstrap 95% CIs** (same method

- **One primary hypothesis (H1)** controls the error rate; everything else is

- H2 mechanism rule: `arm3i_noq ≤ ledger < arm3i_q` (with CIs) ⇒ quarantine is the

  at belief-to-action binding**, which is a reportable result. We will **not** respond by
  adding action nudges to the frozen arms; that is a separate controller ablation.

## 6. Pre-registered expected-outcome scenarios (guards against post-hoc storytelling)

### 7.1 Amendment — failure classification (human researcher, 2026-07-25)

Made **before any confirmatory seed has run** and before any Arm-3 outcome inspection.
Prompted by a measured defect, not by an outcome: see `experiments/worker_replacement/
BELIEF_LAYER_DIAGNOSIS.md`.

**Why.** Two independent code defects made §7's central distinction inexpressible:

1. `invalidates_arm` is `self._failures > 0` — every failure class increments one counter,
   so an exhausted transport retry and a genuine parse failure are indistinguishable.
2. The retry loop catches only `TimeoutError`. Every other transport failure (HTTP 429,
   5xx, connection reset, read error) arrives wrapped as `LLMInferenceTruncationError`,
   is therefore **never retried despite §7 naming upstream 5xx as retryable**, and
   invalidates the cell on first occurrence under a name indistinguishable from a
   semantic failure. Measured incidence: 16 HTTP 429s in 96 calls on one pinned endpoint.

Uncorrected, this would have reported ordinary rate-limiting as genuine extractor failure
and barred us from correcting it by our own discipline. It is independent of the
comparator nondeterminism findings: a 429 would misfile a cell even with a perfect
extractor.

**Amendment.**

- **Transport class (retryable, bounded, byte-identical).** Defined by **principle, not by
  a closed list**: a failure is transport-class iff it cannot have been caused by the
  content of our request or by the model's judgment — i.e. it carries no information about
  the object of measurement. Illustrative and explicitly **non-exhaustive**: transport
  timeout, upstream 5xx, HTTP 429, and the connection-level family (connect/read/write
  errors, connection reset, protocol errors, pool and client timeouts).
  The 5xx and timeout cases are a **compliance fix** — §7 already named them; the code
  under-implemented it. The rest is a genuine **enumeration amendment**.
  A closed enumeration of library exception names is deliberately avoided: it is brittle
  across dependency changes and would silently reopen the gap this amendment closes. The
  open principle is safe **only because the fallback is conservative** — anything not
  explicitly mapped is `unclassified` and therefore invalidating (below). Permissiveness
  requires an explicit mapping; absence of one never grants a retry.
  Failure audits must record counts **per exception type** within the transport class, not
  only the class total, so that a self-inflicted pattern (e.g. pool timeouts from our own
  concurrency) is visible rather than hidden inside an aggregate.
  _Widening of the connection-level family beyond the two names first drafted was raised
  by Research Engineer and approved 2026-07-25 on the principle above, not adopted
  silently._
- **Semantic/extraction class (invalidating, never re-rolled):** parse and validation
  failures. The v2.5 discipline is unchanged and unweakened for this class.
- **Unclassified (invalidating):** where the original exception class is unrecoverable
  **or recoverable but not affirmatively mapped**, the cell invalidates. Conservative by
  default — we do not retry what we cannot name.
  `parse_validation` is reserved for exception types **affirmatively recognised** as parse
  or validation failures. An unrecognised type must **not** default into it: both buckets
  invalidate, so nothing changes about cell survival, but filing an unknown error as
  semantic would overstate the extractor's failure rate and understate infrastructure
  noise — the precise misattribution this amendment exists to correct.
- **Implementation invariant (load-bearing).** The classifier must be applied to **every**
  exception, not to a pre-filtered set. A catch clause enumerating exception types
  reintroduces the closed-list flaw at a lower layer: any type outside the tuple escapes
  unrecorded, which is worse than misclassification because a misclassified failure is at
  least counted. Classification decides what invalidates; the catch site never does.
  Narrowing the catch clause "for clarity" silently voids the principle above.
- Retry exhaustion on a transport-class failure is recorded as its own category, not as a
  semantic failure. Regeneration remains permitted only **before outcome inspection**.
- Failure audits record the **unwrapped** exception class. Per-class counts are reported
  for every cell whatever the outcome.

**What this does not change:** no endpoint, no metric, no arm, no hypothesis, no decision
rule, no seed count. It does not license re-rolling any semantic failure.

### 7.2 Amendment — acceptance gates must be repeat-based (2026-07-25)

A single-shot gate is not a reproducible criterion. Byte-identical requests were measured
returning 19/20 and 15/20 an hour apart, and the comparator is nondeterministic at
temperature 0 (within-backend, seed fixed). A one-shot "recall = 100%" therefore samples a
distribution and reports a point.

- Gate criteria are stated over **k repeats with the tolerance and k both recorded** (e.g.
  recall = 100% on k of k), never as a single pass.
- Every gate invocation runs a **canary** first — a synthetic case asserting the scorer can
  read the comparator's output end to end — which must **fail loudly** when it cannot.
  Rationale: the v2.6 gate's silence was read as a pass for an entire development cycle.
- **Re-clearance path** for the comparator, superseding §0's void certification:
  1. structural/unit tests green;
  2. per-judgment stability measured across the full corpus, ~~hard vs clean split~~
     **diagnostic vs non-diagnostic split** — see (a) below;
  3. run-level exposure — expected wrong verdicts per cell, reported **separately** for
     diagnostic and non-diagnostic judgments (they are different costs and are not summed);
  4. the gate criteria re-run k-repeat, canary armed — **all three**, see (b);
  5. per-class failure table per §7.1;
  6. **affirmation gate per §7.9** — see (c).
  Only then may a pin be proposed.

**Amendments to this path, 2026-07-26.** Recorded rather than silently edited, because a path
that enumerates what must be measured is exactly the kind of prose that decays while the
criteria around it move — the §9 pattern, in this document, about itself.

- **(a) Step 2's split was stale.** It specified hard vs clean, which was measured and showed
  **no meaningful difference** (0.850 vs 0.863). The split that carries information is
  **diagnostic vs non-diagnostic**, which is also the axis §7.9's two halves are defined on.
- **(b) Step 4 said "the four gate traces" and named two criteria implicitly.** There are now
  **three**: diagnostic-contradiction recall, false contradictions on competent no-change
  scopes, and §7.9's affirmation gate. Under §7.7 `diagnostic_comparison_recall` also changes
  form — see §7.7 and the re-clearance design's §7 — so "the four gate traces" must mean the
  traces re-run against the **shipped** configuration and its **current** criterion set, not
  the set that existed when this path was written.
- **(c) Step 6 did not exist when §7.2 was written and §7.9 did not add itself to this list.**
  Without step 6 a run could satisfy all five original steps and **never measure affirmation** —
  a criterion added this morning, unmeasured by the path that certifies the comparator. That is
  the defect this document has recorded seven times in other people's machinery, committed here
  in its own.

### 7.3 Amendment — cell execution order must be randomized (2026-07-25)

**The defect.** `_resolve_cells` iterates `for seed in seeds for (arm, observability) in
cells`, so every seed runs the arms in the **same fixed order**. Arm identity is therefore
perfectly confounded with execution position, and the position order
`native → summary → summary_log → ledger → arm3i_noq → arm3i_q → arm3t`
**is the ladder contrast itself** (§1).

**Why this is disqualifying rather than untidy.** Byte-identical requests were measured
returning 19/20 and 5/20 forty minutes apart. A seed block is seven full episodes — tens of
minutes — so drift operates on exactly the relevant timescale. A monotone time trend would
therefore manufacture a monotone ladder effect, in the predicted direction, identically
across all five seeds. It would not look like noise; it would look like our hypothesis.
Paired difference scores against same-seed `native` do not protect against this: `native`
is always first in its block and `arm3t` always last, so the pairing preserves the
confound instead of removing it.

**Amendment.**

- Cell execution order is **randomized across the whole matrix**, not blocked by arm or by
  seed. The ordering seed is recorded in every manifest so the sequence is reconstructible.
- Every cell records **wall-clock start/end** and its **serving-backend mix** (available via
  the attribution hook, §7.1).
- Drift is **reported as a diagnostic, not assumed absent**: test the association between
  each endpoint and (a) execution position, (b) backend mix. A detected association is
  reported alongside the result, never silently absorbed.
- Cost is nil — the same 50 cells in a different order.

**Scope of the concern.** Any blocked comparison in this project carries the same unknown
time confound, including Phase-1's observability conditions if they were run in fixed order.
That is flagged for checking, not asserted. The qualitative findings that survived
separately-run replication and a positive control (packaging necessary and sufficient) are
not in doubt; fine-grained rates from blocked designs are.

### 7.5 Amendment — guarding the designed stakeholder absence (2026-07-25)

Replaces withdrawn §7.4. Scoped to what the evidence actually supports.

**The real state.** `_profile_candidates` excludes `agent_type == "stakeholder"` by design,
so stakeholder review scopes correctly have no profile prior — one pair per cell. Any
accepted relation on such a pair reaches an **unguarded** `self._temporal_priors[key]`, in
two places (`_update_temporal_beliefs`, and `temporal_snapshot()`). That killed an arm3t
cell outright when a false contradiction on a task-failure notice created a relation there.

**Amendment.**

- Missing prior for a stakeholder scope resolves to an explicit, **named uninformative
  prior** — documented as "no competence expectation is formed for stakeholders, by design",
  not written as a defensive `.get(key, 0.0)`.
- Both unguarded accesses are guarded. `temporal_snapshot()` is included: "safe because it
  can only see keys the updater created" is an invariant nobody asserts, which is the
  property every defect in this session's tally shares.
- **Invariant asserted:** no *non-stakeholder* (worker, scope) carrying an accepted relation
  may lack a profile prior. The guard covers the designed absence only and must not be able
  to absorb a future construction gap silently.
- Option (iii) independently removes the trigger that surfaced this, so the guard is
  defence-in-depth rather than the primary fix.

**What this does not change:** no endpoint, metric, arm, hypothesis, decision rule, seed
count, packet construction, emission rule, or config tag. Arm-2 ledger and byte-identical
prefix untouched. `arm3t` remains the only arm that reads `_temporal_priors`.

### 7.6 Decision — no aggregation over repeated draws (human researcher, 2026-07-26)

**Standing and permanent.** The belief layer runs at **n=1**. No majority voting, no
self-consistency, no aggregation over repeated draws of the same judgment, in any arm or
any future revision of the comparator. This is a research decision, not an inference from
the evidence below.

**Rationale as given:** aggregation is a workaround rather than a fix, and it buys
reliability with call volume. A capable model should not need it for a judgment this
simple; where it does, the calling convention is what should change.

**Evidence, stated in both directions so the record is not misleading.** The decision is
better supported now than when it was made, but the evidence does not say aggregation is
useless in general — it says the failures that carry the harm here are the kind aggregation
cannot fix.

- **Cannot repair a wrong mode — observed three times.** The original Bug 2 mixed claim
  (0/20 and 19/20 *supports* on a degraded worker); the fallback failure notices (74%, then
  20.5% after the wording fix, modal `contradicts_fit`); and the decisive false-contradiction
  cluster (4 judgments at 8–10 of 10 contradicting methods that *match* their parent
  requirement). In every case majority voting returns the wrong verdict with **higher**
  confidence.
- **Would repair minority deviation around a correct mode — which also existed here.** Three
  tool-capability judgments with correct modes at 16/20, 13/20, 15/20 (reviewer-reproducer,
  independent). Aggregation is the textbook remedy for exactly that shape.
  **Caveat added 2026-07-26 (reviewer-reproducer):** those three judgments are on the
  tool-capability clause, whose input §7.7 changes — so this bullet's evidence may not
  survive the amendment sitting next to it. It is retained as the state of evidence when
  §7.6 was decided, not as a current measurement. The ban is unaffected either way; the
  point is not to let an evidence bullet outlive its measurement.

**Consequence, and it is the operative one.** The false-contradiction bar must be met **by
construction** — input scope, prompt, or requirement/artifact alignment — and no longer has
a sampling route. Every candidate fix from here is a change to what the comparator is asked,
not to how many times it is asked.

**Code.** `clause_vote_depth`, the adaptive-stopping mechanism, and its equivalence tests are
to be **removed**, not left switched off. Earlier guidance to retain them assumed the
decision might be revisited; under a permanent ban a live knob for a banned technique is a
hazard of the same class as a comment asserting a check that does not exist. Git history
retains the implementation if the ban is ever lifted.

### 7.7 Amendment — judge against the requirement, not the clause fragment (2026-07-26)

**The defect.** The comparator judged a **fragment of the requirement** against a **fragment of
the artifact**. The clause splitter decomposed requirements; the atomic ledger decomposed
artifacts; the two decompositions were independent and neither aligned to the other. Measured
consequence: four judgments contradicting at 8–10 of 10 on methods that **match** the standard
their parent requirement names — ~30/40 pooled on the affected cluster, against a
zero-tolerance false-contradiction bar.

**Why the fragment was never the right unit.** The clause splitter was an implementation step,
not a scientific choice. The manager's question is whether a worker's artifact fits its
requirement — nothing in the research question concerns clauses. The splitter acquired
scientific significance nobody granted it.

**Amendment.** The judgment unit becomes **(parent requirement, method claim)**. The clause
splitter leaves the **input path**; it is retained only for constraint identification in
scoring, where it is still needed to map a judgment to the constraints it covers.

**Measured before adoption** (all interleaved, baseline carried in the same run):

| | current | parent |
|---|---|---|
| false-contradiction cluster (4 judgments) | 30/40 | **0/40** |
| diagnostic recall (8 targets) | 8/8, 79/1/0 | **8/8, 80/0/0** |
| distinct questions in corpus | 141 | **62** |
| scored populations | 8 diagnostic, 3 exonerating | **unchanged** |

No hedging (zero `neutral`) and no averaging (zero `supports_fit`) under `parent`. Recall was
tested on the population where the change has **no informational gain and only distractors to
lose**, and held.

**Requirements.**
- `ARM3_DETERMINISTIC_EXTRACTOR_VERSION` is bumped so the config tag distinguishes pre- and
  post-amendment measurements. The tag hashes prompts, schema and versions — **not** input
  construction — so without this bump two materially different configurations would share one
  tag, which is the provenance failure this document has recorded five times.
- §7.2 re-clearance runs **once**, on the post-amendment comparator. The k=3 gate sequence
  measured the superseded configuration; it is retained only as between-period data.
- The largest non-method family (`"The outlier tool accepts column='all'…"`, 24 judgments,
  measured ~27% false contradictions) is **untested under `parent`** and must be measured
  before any pin.

**Limits, stated plainly.** The evidence is **twelve questions** — four false-contradiction and
eight diagnostic. The 130 unlabelled questions are unmeasured under either arm. A change that
alters every judgment in the corpus deserves better than twelve; it has survived every test we
have, including the one designed to break it, and that is not the same as validated.

**The tests were not sampled from the corpus** (reviewer-reproducer, 2026-07-26). Both
populations were selected *because they were already known-interesting* — the four because they
contradicted decisively and wrongly, the eight because they are the planted diagnostics. The 130
unmeasured questions are therefore **not a random remainder**; they are the ones nobody had a
reason to look at. So "survived every test we have" is true and carries no implication about the
corpus, because the tests were chosen where problems were already visible. Any rate quoted from
these twelve is conditional on that selection and is not an estimate of corpus behaviour.

### 7.8 Amendment — parse failures are no-answer, not wrong-answer (2026-07-26)

**The defect.** §7.1 classes parse/validation failures as semantic, hence invalidating and
never re-rolled. Measured incidence: **0.34% per draw** (7 of 2,060), giving
**P(≥1 per cell-repeat) = 25.3%** at 86 draws — observed in 5 of 24 cell-repeats. Across 50
cells that invalidates roughly a quarter, and for **paired** analysis, which needs both cells
of a pair, roughly **44% of pairs** at independence. On n=5 seeds with no seed-adding
permitted, that is a power problem rather than a bookkeeping one. It is caused by transport
and model behaviour, **not** by the input path, so it is independent of §7.7 and survives any
decision about the comparator.

**Why the original classification was wrong under §7.1's own principle.** §7.1 defines the
transport class by whether a failure *carries information about the object of measurement*. A
`ValidationError`, a `JSONDecodeError`, an `InstructorRetryException` carries none: the model
has not rendered a wrong verdict, it has failed to communicate one. The operative distinction
is therefore not semantic-versus-infrastructure but:

- **NO ANSWER** — the response could not be parsed into a verdict. **Retryable**, bounded,
  byte-identical.
- **WRONG ANSWER** — a verdict was produced and is wrong, or violates the response contract in
  a way that reflects the model's compliance (the **shape-invalid** class). **Invalidating,
  never re-rolled.**

The v2.5 discipline exists to stop a *bad answer* being re-rolled until it becomes good. A
parse failure is not a bad answer; retrying it re-rolls nothing about the judgment. Shape-invalid
responses remain invalidating, so this is **not** a general licence to retry.

**HELD, NOT ADOPTED (revised 2026-07-26 after reviewer-reproducer).** Approved in principle by
the human researcher, then withdrawn from effect pending evidence. Three objections, all
sustained:

1. **Byte-identical retry is not a no-op on a nondeterministic instrument.** §7.1's retry was
   safe for transport because transport failures are independent of what we sent. This
   comparator flips at temperature 0 with a fixed seed. So "retry until it parses" is *drawing
   again on the same judgment and keeping the draw that returned* — selection over repeated
   draws, discarding those that failed to parse. Not aggregation in §7.6's sense (first success,
   not majority), but the same family §7.6 exists to close. It biases only if parse failure is
   **independent of judgment difficulty**, which nobody has measured: if harder or more ambiguous
   judgments truncate more often, retrying preferentially recovers easy resolutions and the
   surviving verdicts are systematically more confident than the population.
2. **It changes §7.1's principle rather than applying it.** §7.1's test is whether a failure
   *could have been caused by the content of our request*. A `JSONDecodeError` from truncation
   *can* be — a longer payload truncates more often — so it fails §7.1's actual test while
   passing the no-answer/wrong-answer one. The lead-scientist argument that this "applies §7.1's
   own principle consistently" was **wrong**: it substitutes a different discriminator. §7.1
   states that permissiveness requires an explicit mapping and that absence never grants a
   retry; swapping the discriminator is the broadening that clause exists to prevent.
3. **It is unevidenced, and cost-relieving, and was proposed immediately after the cost was
   quantified.** `gate_session.py:146-147` records `failures_by_class` but not the failure
   *type*, and the per-type audit never reaches the session file — so of the 7 failures nobody
   can say how many were `JSONDecodeError` versus `ValidationError`, which is the split the
   amendment turns on. A change that relieves a cost, proposed minutes after that cost was
   measured, is held to a **higher** evidence bar, not the same one.

**The class is mixed, so the amendment could never have been as broad as written.**
`JSONDecodeError`, `IncompleteOutputException`, `ModeError` are candidate no-answers.
`ValidationError` / `AsyncValidationError` fire on responses that **were** parsed and then failed
the schema — compliance information, invalidating under either discriminator.
`InstructorRetryException` is a wrapper, classified by its cause. The two Pydantic-side types
indicate *our* defect and should raise rather than be counted.

**Sequence before this is reconsidered:** (i) record the failure type in the session file — one
line; (ii) obtain the type breakdown from the k=3 re-run as a by-product; (iii) attempt the
**cause** instead of the class — DIAGNOSIS §5 already records the nested-`$defs` schema
fragility, and reducing the parse-failure rate lowers cell loss without touching the
invalidation discipline or reopening §7.6. If the rate falls, this amendment is unnecessary.

### 7.9 Amendment — the false-contradiction bar gains an affirmation floor (2026-07-26)

**The loophole.** Under-affirmation does not breach a false-contradiction bar — a `neutral` is
not a contradiction. So every mechanism that reduces the comparator's willingness to contradict
makes the bar **easier** while making the instrument less useful, and the limit case — a
comparator that never contradicts — passes perfectly and detects nothing. A zero-tolerance
false-contradiction bar with no affirmation floor is **satisfiable by degradation**.

This is not theoretical: four measured trades (JSON payload, the `silence` instruction, the
`:1728` aggregation rule, and §7.7 itself) each bought specificity with sensitivity, and none
moved only the errors.

**Two corrections to the argument as first written (reviewer-reproducer, 2026-07-26).**

*The muteness limit case was overstated.* "A comparator that never contradicts passes the bar
perfectly" is false — total muteness fails `diagnostic_contradiction_recall`, which is a gate
criterion at 100%. The two existing gates jointly block total degradation, and an argument
resting on that limit invites the reply that the gate already handles it.

*The surviving version is narrower, measured, and stronger.* The trade is **asymmetric**:
contradiction recall held 8/8 under (a) while **4 of 15** expected-support questions decayed to
`neutral`. So **partial affirmation collapse with diagnostic contradiction detection intact
passes both existing gates while degrading the instrument** — contradiction recall does not see
it, the false-contradiction bar is *helped* by it, and it is the observed failure mode rather
than a hypothetical.

*And nothing preregistered would show it.* `change_relevant_relation_recall` is **not in this
document** — zero occurrences; it exists only in code. §3's secondary list contains no
affirmation metric. So affirmation loss is currently invisible to every preregistered measure.

**Amendment.** The bar becomes paired: **the instrument must be determinate where the truth is
determinate, in both directions.** False contradictions on competent no-change scopes remain
**0**.

**RESOLVED (2026-07-26): gate the CONTRAST; report polarity symmetry as the descriptive
absolute.** The researcher's chosen route — derive the level from what the exonerating analysis
needs — was attempted and **retired as the wrong species of criterion**, not merely as one that
ran short of evidence:

- It derives a floor from an endpoint the failure *flatters*. `fp_ctrl_q` measures spurious
  rerouting, which false **contradictions** drive; affirmation decay produces fewer supports
  without producing more contradictions, so the endpoint improves as the instrument degrades.
- The reductio is this document's own §6. If instrument gates follow from what downstream
  endpoints need, the ~50% controller-binding null licenses **no** belief quality at all — a
  manager that ignores beliefs needs nothing from the belief layer, so every gate could be set
  to zero. That would apply equally to contradiction recall.
- Therefore: **an instrument gate must be a property of the instrument** — does the belief layer
  faithfully represent what is visible — and not a property of what a consumer does with it.

**Gate:** affirmation on determinate matches **no worse than the same-session pre-(a)
baseline**, per draw, §2's in-run `current` arm supplying the comparison. That is a property of
the instrument, answerable, and actionable.

**Descriptive absolute — polarity symmetry on determinate cases.** The comparator answers
determinate **mismatches** at 1.000 and determinate **matches** at 0.582, on populations that are
equally determinate by construction. An instrument should not be dramatically more willing to
assert one polarity than the other where the truth is mechanical either way. Reported, not gated,
with two caveats:

- *Some asymmetry is legitimate.* Detecting a mismatch requires finding **one** conflict;
  affirming a match requires ruling **all** of them out. These are not symmetric tasks, so no
  equality criterion is proposed — only that 1.000 against 0.582 is a large gap on mechanically
  determined cases.
- *The gap must be reported for BOTH arms.* Under §7.7 the requirement carries more clauses for a
  method to be silent about, so (a) may **widen** the asymmetry structurally. If the gap is
  comparable under `current`, it is a comparator property; if it widens under (a), it is a further
  cost of (a). The contrast measurement supplies exactly this, so it costs nothing extra.

The 0.80 threshold is withdrawn. Its derivation is recorded below because the error is
instructive.

**Why 0.80 was withdrawn.** It was chosen as "somewhat above the observed 0.73". **That 0.73 does
not exist**:
it pooled two populations — 7 determinate matches plus 4 determinate mismatches out of 15
questions — and was reported as a match rate. Corrected:

| population | modal | per draw |
|---|---|---|
| determinate mismatches | 4/4 = 1.000 | 80/80 = 1.000 |
| determinate **matches** | **7/11 = 0.636** | **32/55 = 0.582** |

**POPULATION, added 2026-07-27 — every figure above describes a narrower population than its
phrasing implies, and the fix is to name it rather than to restate the rates.**

| figure | population it actually describes |
|---|---|
| `32/55 = 0.582` | **11 of 12** determinable match questions — all **audit-scope**, all **prose** method strings. The excluded item is `mean_plus_two_sd`: the only calibration-scope question and the only identifier-form method. Direction of the correction **unknown**; "near-verbatim, therefore easy" assumes surface form is inert, which this investigation falsified. |
| `80/80 = 1.000` | **4 of 4** distinct mismatch questions — **complete**. The "8" seen elsewhere is the batch-replicate count, not a population. |
| the **contrast** between them | like-for-like in count and **not in character**: 11 questions spanning **3** requirements against 4 questions under **1** requirement, all four the same divergence (a z-score/mean+2·SD estimator claimed against a percentile requirement) in four spellings. So `1.000` is perfect detection of **one divergence type against one requirement**, not evidence of general mismatch detection. |
| both | measured on run **`c91475579309`**. The label `v2.6` is **ambiguous** — a second run, `71770f08bfd5`, also bore it and nothing here used it. |

_This section has now been wrong three times about which population its numbers describe: the 0.80
threshold pooled two populations; correcting it to 7/11 and 4/4 fixed the pooling; nobody then
re-checked whether 11 and 4 were still the sizes. **Naming the population beside each figure is the
fix that prevents a fourth — correcting an instance does not.**_

So the affirmation gap against 0.80 is **~0.22, not ~0.07**. The researcher approved an absolute
floor on the smaller figure. Approving a floor one is 7 points under is a tuning decision;
approving one 22 points under is a decision about whether the instrument can meet the criterion
at all. He was shown the first and would be held to the second, so the level goes back to him
rather than being corrected in a table.

**Unit is part of the criterion.** Modal and per-draw differ by 5 points here and production runs
at n=1, so **per-draw is the operative reading**. A floor stated without its unit gets assessed
at whichever reading the assessor reaches for.

**The contrast is reported beside the absolute, always.** §2 already carries the `current` arm
in-run, so it costs nothing. At 0.582 the absolute number alone cannot distinguish "(a) broke
affirmation" from "affirmation was always ~0.58 and (a) is neutral on it" — and those imply
opposite actions, the first putting reversion on the table and the second making reversion pay
the false-contradiction cost for nothing. A failing floor without a contrast says you failed
without saying what to do. It is also a reliability check on the floor itself, since levels here
have moved 2.2× between sessions and an absolute reading at k=3 can pass or fail on session luck.

**This is not the promotion §4 forbids.** §4 bars post-hoc promotion of a secondary *contrast* to
primary. An affirmation floor is an **instrument acceptance gate**: it constrains the measuring
device, not the hypothesis, and touches no endpoint, no arm, no error rate, and not H1.

**Population limit.** The labelled exonerating set is **3 questions in one cell**, so the
affirmation floor cannot be honestly assessed on it. The 15-question construction-derived set is
better evidence and is not the preregistered population (§7.2 step 5 remains NOT SATISFIED).
Setting a floor does not repair the population; expanding the labelled exonerating set is the
only thing that would.
