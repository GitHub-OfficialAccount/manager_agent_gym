This is the authoritative, consolidated research brief for the current AHT direction. It supersedes earlier looser summaries in CLAUDE.md. Read this first before doing any implementation work on the experiment.

> We state a hidden-mode POMDP where a worker's behavior silently changes mid-episode, measure the reward an LLM manager loses as we vary only how observable the change is, characterize completion-as-competence conflation in a controlled capability-change cell, and test whether information-preserving representations of ordinary work evidence recover that loss.

In one glance: this project studies whether an LLM manager can detect and route around an **unsignaled mid-episode behavioral change** when its only evidence is ordinary work artifacts. Capability/toolset change is the first, cleanly graded lever used to instantiate behavioral change; model+prompt change is the intended generalization lever. Phase 1 measures the cost of not being told. Phase 2 tests increasingly structured, but information-preserving, representations of the same silent evidence.

## 0. Formal grounding (read first, governs all wording)

Masters et al.'s MA-Gym is formalized and implemented as a **genuine multi-player POSG**: the player set is `I = {M} ∪ W`, workers are decision makers with per-agent policies, and the paper uses the PONE solution concept. Do not describe the source environment as single-player or claim that workers lack actions.

The evaluation fixes every non-manager co-policy as a well-defined history-to-action mapping. Stochastic LLM workers satisfy this requirement. Once those co-policies are fixed, the interaction is equivalent **from the manager's perspective** to a single-agent POMDP: worker behavior is integrated into the manager-facing transition kernel. This is an evaluation-time reduction, not a redefinition of the underlying POSG.

Augment the reduced state with a latent worker-behavior mode `θ`. The mode switches once through a rare/exogenous transition from the old worker mapping to the replacement mapping. On this augmented state space, `T` is stationary; only the manager's marginal experience appears non-stationary when `θ` is hidden. A model, prompt, or toolset swap is a cause of the mapping change, not the formal object being inferred. It does **not** change the manager's action space `A_M`, whose ~15 typed orchestration actions remain constant.

Full, partial, and silent conditions are three observation functions over this one hidden-mode POMDP. They share the same augmented `S`, manager action space `A_M`, stationary `T`, and `R`; only `O` differs in what it reveals about `θ`. The Phase-2 digest is an approximate belief state over `θ`, yielding an estimator-controller decomposition: the belief module estimates teammate mode and the frozen manager policy chooses orchestration actions.

Both this capability-change setting and classical Scenario-2 policy shifts can be represented as hidden-mode changes in the manager-facing dynamics. They differ in the driver of the mode change (capability/toolset/model versus policy/judgment), not in formal kind. Do not call this a "generalization of Scenario 2."

**RL stance:** retain the POMDP problem statement, return, controls, and oracle comparison because they define the independent variable and evaluation. Drop RL as the Phase-2 method: the manager is a frozen pretrained policy and adaptation happens in context, not through weight updates. Trained ICRL and meta-learning are roads not taken in the current scope.

## 1. Core research questions and phase transition

Can an LLM manager detect and recover from an unsignaled mid-episode change in a teammate's behavior when the only evidence is subsequent work and interaction? The manager runs an orchestration policy based on the team's apparent behavior and capabilities. A teammate change (a `W`-mutation switching the active worker mode `θ`) can invalidate that policy; we measure whether and how quickly the manager recovers. Capability loss is one controlled cause of behavioral change, not the scope of the research claim by itself.

The work now has two explicitly separated phases:

1. **Characterization:** When does native LLM orchestration detect and recover from fully signaled, partially signaled, and silent teammate changes? This phase establishes the adaptation gap and its causes.
2. **Silent-change recovery method:** Can an evidence-grounded, time-sensitive belief about teammate capabilities close the *avoidable* performance gap between silent change and fully informed recovery, without hidden ground truth, private worker policy, or perturbation metadata?

The primary toolset cell has completed its paired five-seed characterization and clears the gate for the first Phase-2 ablation (§11). Generalization remains untested across a second perturbation and additional workflows, so do not report the current result as a broad AHT effect.

Recovery is re-orchestration ONLY (retry / reassign / refine / re-decompose tasks). A retry reopens the same failed task node, optionally under a different worker; it does not edit the worker. The manager's action space `A_M` contains no action to edit, repair, or swap a worker — so the manager can route around a degraded worker but never fix one. Any definition of "successful recovery" must be expressible purely as re-routing. (This is a hard constraint from the action-space definition, not a design preference.)

## 2. The two change levers

The hidden object of interest is the worker's changed behavior. We induce it through two independent levers, run separately for clean attribution:

- **Lever A — model ∪ prompt** = a "judgment/reasoning" change.
- **Lever B — toolset** = a "capability" change.

Both are implemented as mutations of `W` that switch the active worker history-to-output mapping, or equivalently the latent mode `θ` in the manager-perspective POMDP (per §0). Lever B is the primary mechanistic cell because its consequences are deterministically gradeable; it does not redefine the project as tool-loss detection. Lever A tests whether the same observation and representation machinery transfers when behavioral evidence is diffuse and no explicit method mismatch is available.

**Why model+prompt are bundled, not separate:** isolating model-only vs. prompt-only is too diffuse to attribute (model identity affects reasoning depth, instruction-following, verbosity, hallucination at once). Bundling gives a coarser but measurable "judgment change" contrast against Lever B's "capability change." The pilot finding that prompt-only swaps produced no measurable degradation (§6) reinforces this — isolating prompt's solo effect would claim a distinction the pilot couldn't detect.

**Lever A grading caveat:** its effect is diffuse/stylistic, so scope Lever A's evaluated tasks to checkable numeric/factual answers to avoid the judge-sycophancy problem (§6).

**Lever A ambient-signal asymmetry (track, don't suppress):** a model∪prompt swap likely carries a stylistic tell (word choice, verbosity, rhythm) that a toolset swap structurally cannot — a missing tool has no "style." So under "silent," Lever A may leave more ambient trace than Lever B. This is not leakage to suppress — using ambient evidence is exactly what a good ad hoc manager should do. But it means a cross-lever comparison must distinguish "manager reasons better about judgment-shifts" from "more ambient signal was available for that lever." The frozen shadow probes in §10 quantify this rather than merely asserting it.

## 3. Literature positioning

- Scenario 2 (mid-episode behavior change: HBA, ConvCPD, ODITS) is the closest parent.
- Frame the relationship per §0: both are hidden-mode changes in manager-facing dynamics, with different drivers (capability vs. policy) — not a "generalization."
- Phase 1 implements no explicit AHT inference mechanism; its open question is whether an LLM's native reasoning substitutes for explicit statistical machinery when behavior is legible text.
- Phase 2 stages information-preserving representations before introducing a temporal teammate belief, rather than copying a classical policy tracker literally. Its closest conceptual bridges are responsive/additive beliefs under switches (HBA), recency-sensitive expert weighting (PPAS), explicit changepoint evidence (ConvCPD), and continuous teammate-state tracking (ODITS). The LLM-specific question is which representation properties are necessary for textual execution evidence to support comparable responsiveness without a known discrete policy library.

### The three assumptions this experiment breaks

Classical mid-episode AHT methods — including HBA, ConvCPD, CABPR, and fast-teammate-adaptation methods — generally assume some combination of:

1. observable teammate actions on which to compute likelihoods;
2. a known, finite type or policy library; and
3. statistical rather than semantic evidence.

The nearest LLM analogue, ReCollab, retains all three: it classifies a static per-trajectory type from a known set during a fixed 20-step probe window, routes policies once to avoid instability, and leaves online adaptation as future work. Here there is no teammate action stream in the formal interface, no type library, and the admissible evidence is unstructured execution text and artifacts. Capability degradation is the particularly adversarial sub-case in which the worker remains cooperative and operational while only the quality or methodological fitness of its artifacts changes.

LLM multi-agent monitoring systems such as SentinelNet and A-Trust instead target malicious agents using message features and trained detectors. This project targets benign mid-episode behavioral change using ordinary execution artifacts and interactions, beginning with a controlled capability-loss lever and testing transfer to model+prompt change. The claimed combination is therefore: **LLM manager + silent mid-episode teammate behavioral change + ordinary execution evidence without a teammate-action stream + observability as the independent variable**. Treat this as the novelty target to verify in the final literature review, not as permission to overclaim priority before that review is exhaustive.

## 4. Observability conditions (primary IV)

Three tiers:

1. Fully signaled — manager told a change happened and what changed.
2. Partially signaled — told something changed, not what.
3. Fully silent — no explicit notification.

**Formal target (state in any writeup):** the three tiers are different observation functions `O` over one augmented hidden-mode POMDP, sharing `S`/`A_M`/`T`/`R` and differing only in `O`. Reward(1) − reward(3) is therefore a comparison across observation functions over identical latent dynamics.

**Observability separation completed (2026-07-15):** objective worker mutation and manager observability now compose as separate `PerturbationDefinition + ObservabilityDefinition` objects. Silent, partial, and full register the same canonical mutation; the observation policy independently schedules the baseline, uncertain, or current capability projection and any generic/specific announcement. Tests and a direct smoke check confirm that all non-control schedules and post-change canonical worker configurations are identical while only the manager-visible projection differs. This clears the mandatory methodological gate before Phase 2. The shared strategy-neutral prior that agents may evolve stays constant across all conditions and is not part of a perturbation.

**Definition of "silent" (precise):** the real tool/model/prompt mutation occurs, no announcement is sent, private system prompts remain hidden, and the manager receives no updated configuration declaration. The worker's changed output still reaches the manager via `recent_messages` (C), workflow/resources (R), and normal task outcomes. So "silent" = no explicit change signal, NOT zero information. Do not redact ambient behavioral evidence.

> ✅ **Confirmed 2026-07-12:** `redact_agent_config()` has exactly one call site (`interface.py:164`), applied only inside the list comprehension building `available_agent_metadata`. `recent_messages` is built independently three lines above (`interface.py:130–142`, sourced from the communication service) and is never passed through the policy object. The two channels are structurally decoupled — "silent" cannot accidentally suppress ambient evidence. Bonus: `workflow_summary=workflow.pretty_print()` is also unfiltered by the policy, likely a second ambient channel beyond messages.

**Primary metric:** observability gap = reward(1) − reward(3).

| Condition | What `O` reveals about the change |
|---|---|
| Full | The change, its identity, and timing |
| Partial | That something changed, but not what |
| Silent | No explicit signal; only ordinary work artifacts and outcomes |

## 5. Two channels of O are orthogonal — do not conflate

- **Config channel**: implements full/partial/silent disclosure of worker configuration and announcements. It must not carry engineered performance inference.
- **Representation channel** (`observation_aid`): `none` is the native baseline; `generic_summary` is Arm 1. Later structured evidence/belief renderings belong here too. The legacy `quality_digest` field remains unpopulated. Every populated aid must be derived only from admissible manager-visible history, so it changes representation rather than information.

These are independent variables. The observability tiers are the config channel; any detector work is the quality channel.

## 6. Grading (deterministic spine)

Use deterministic numeric reward `R_check` as the experiment endpoint. The experiment-local native LLM evaluator is disabled from 2026-07-17 onward: it added one judge call per episode, was not used online, and was substantially noisier than `R_check` in the completed characterization matrix. Historical manifests retain native reward for auditability; new runs omit it. The engine's reward plumbing remains unchanged and simply has no experiment rubric to execute.

- Deterministic grading is the fix for **limitation #2**: the LLM judge scores good-sounding output well regardless of correctness.
- **Limitation #1** (from pilot): workers differ only by system prompt with identical model/tools, and prompt-only swaps showed no meaningful degradation — motivating the toolset lever as a real, checkable capability gap.

## 7. Toolset design (Lever B)

Avoid strict superset (senior ⊃ junior collapses orchestration into "always pick who has more tools" = a detection problem, not orchestration). Instead:

- Shared baseline both tiers have (e.g., mean, SD).
- Senior: additional depth for most tasks (quantiles, regression, correlation).
- Junior: one narrow tool senior doesn't bother carrying (a fast heuristic) — a tradeoff, not a capability senior lacks.
- Senior is weakly directional, not a superset — wins on most tasks, a few genuinely ambiguous. This makes recovery (not just detection) meaningful.
- Same-tier variance allowed (two juniors may differ), but keep junior-junior variance smaller than the senior-junior gap — else "seniority" degrades into per-worker idiosyncrasy.

**Tool-pair vetting rule:** the pair must support a constructible task whose ground-truth answer deterministically requires the capability the weaker tool lacks, checkable against synthetic ground truth. Reverse-engineer the pair from the workflow's actual analysis question.

**Candidate — ✅ linchpin-validated and implemented 2026-07-13:** outlier detection — quantile-capable (`flag_outliers_percentile`, true 95th-percentile cutoff) vs. mean+SD-only (`flag_outliers_zscore`, mean+2σ rule), on skewed synthetic loan-portfolio columns where the two cutoffs diverge; grade the reported count against the known-true count. Empirical result (deepseek-v4-flash, 2 tiers × 4 columns × 2 reps, no retries, real `AIAgent` pipeline): senior scored 1.00 on every cell; junior faithfully relayed the z-rule value every single time (14, 25, 91, 92 vs. truth 100) with **zero** self-correction toward truth — yielding a *graded, column-dependent* gap (junior ≈0.9 on income/amount, ≈0.14–0.25 on dti/rate). Both (a) the gap is real and graded (not binary — junior always outputs a genuine number), and (b) the model does NOT algebra its way around it. The substrate is implemented in `experiments/ds_reroute/scenario.py`. (Backups if a second pair is needed: Pearson-only vs. +Spearman; linear vs. +polynomial regression.)

## 10. Reference conditions and loss decomposition

Reference lines: no-change control (ceiling), oracle/full-information manager (told at injection), native silent manager, method-assisted silent manager, and naive/frozen manager (floor).

A silent manager cannot react before any informative post-change evidence exists. Do not demand literal equality with the oracle when the oracle can act earlier. Decompose loss into:

1. **Irreducible signal delay:** damage before the first admissible observation could reveal the change.
2. **Detection cost:** additional damage after informative evidence exists but before the manager behaviorally responds.
3. **Response cost:** loss after detection caused by poor probing, retrying, reassignment, or downstream repair.

The primary method headline is **oracle-gap closure**:

```text
(R_method_silent - R_native_silent) / (R_full - R_native_silent)
```

Report it alongside absolute `R_check`, because the ratio is unstable when the denominator is small. Also report post-evidence gap closure, which removes irreducible signal delay and more directly evaluates the method.

The observability gap has two conceptually distinct sources:

- **Information component:** evidence unavailable under silent observation, bounded only by the full-information oracle and irreducible signal delay. No information-preserving agent-side method can close it.
- **Computation/attention component:** evidence already present in silent history but not extracted, maintained, or acted upon. Phase 2 is allowed to target only this component.

This distinction is causal only if the method's belief is a history-only transformation of the native silent observations: `b_t = f(o_1, ..., o_t; xi)`, where any internal randomness `xi` is independent of hidden state. Any method input unavailable to the native silent manager turns the intervention into an information treatment and invalidates the representation claim. This is the load-bearing wall of Phase 2, not ordinary experimental hygiene.

The anticipated "this is only prompt/context engineering" objection therefore inverts. An ideal Bayesian agent would gain nothing from the digest. If a real frozen LLM manager improves, the experiment has demonstrated a specific form of bounded rationality and located the avoidable failure in computation/attention rather than information. A Kalman filter likewise adds no measurement information; state estimation remains useful because a real controller cannot condition perfectly on an unbounded raw history. The claim is not that the digest adds evidence, but that it is a minimal representation that repairs a measurable inference failure. If generic summarization captures all of the gain, the stronger belief-state claim fails, and that negative result must be reported directly.

Detection is measured behaviorally (first causally relevant action toward the changed worker) and with two independent shadow probes over the exact stored pre-action `o_t`: (1) whether each worker's behavior/capability may have changed, and (2) what observed evidence informs that assessment. Probe outputs never re-enter the episode. Run the probes independently at frozen evidence/decision points so one answer cannot prime the other. Classify non-engagement, noticed-but-dismissed evidence, stated-belief-only adaptation, and belief-plus-action adaptation. This dissociation also measures the §2 ambient-signal asymmetry.

**Implemented measurement protocol (2026-07-18):** the experiment-local `judgment_protocol.py` freezes the structured probe schemas, wording, deterministic response coding, and protocol fingerprints. `shadow_probe.py` resolves the saved pre-action requests immediately before Batch B/C robust assignments and makes two history-independent calls; results are written offline and never consumed by execution. Probe spec `shadow-probes-v1.1` retains symmetric assessment of all workers but limits evidence recall to the three strongest decision-relevant items per worker; this documented amendment prevents task/field enumeration observed in the initial seed-101 probe. The seed-specific protocol file also freezes relation-level `diagnostic`/`exonerating`/`neutral`/`ambiguous` judgments. `audit_arm2.py` joins these to evidence opportunity, semantic routing, and decision-point prompt sizes. Its separately versioned offline matcher normalizes only equivalent serialization variants (for example, `"method":` versus `method:` and `z-score` versus `zscore`) before applying unchanged semantic labels. This adds no live observation, prompt, action, or manager-flow change.

**Hygiene:** paired designs (same workflow/seed, with/without change, difference scores); bootstrapped CIs; ≥5 seeds/cell; 4–6 workflows stratified by team size/churn, not all 20 (factorial explodes). Consider measuring detection latency in wasted work (rework-weighted tasks completed before intervention) rather than raw timesteps.

## 11. Primary characterization result and phase decision (2026-07-17)

The following gates are complete for the primary toolset perturbation:

- Real workers voluntarily use their tools and return parseable, graded outputs.
- Fixed assignments show immediate and downstream loss without switching the worker off.
- Fully informed recovery is feasible through native reassignment.
- Paired control/full/partial/silent runs completed for seeds 101–105 with 16/16 predefined tasks in every run.

| Condition | Mean `R_check` | SD | Correct robust routes | Downstream `R_check` |
|---|---:|---:|---:|---:|
| Control | 1.000 | 0.000 | 15/15 | 1.000 |
| Full | 0.946 | 0.082 | 12/15 | 0.855 |
| Partial | 0.907 | 0.097 | 10/15 | 0.773 |
| Silent | 0.739 | 0.056 | 1/15 | 0.302 |

The paired full-minus-silent observability gap is `0.207` (paired bootstrap 95% CI `[0.125, 0.286]`), positive on all five seeds. Partial-minus-silent is `0.167` (`[0.054, 0.268]`). Direct robust-audit loss (`0.182`) amplifies to a `0.553` downstream gap.

The traces repeatedly expose **completion-as-competence conflation**. Partial signaling routed the first robust audit correctly in all five seeds, but some managers later returned work to the degraded worker after calling prior degraded completions successful. Silent managers often ignored explicit `zscore` method reports and reused the worker; all tasks still completed, making completion rate non-discriminative. Completion proves availability, not method, quality, fit, or retained capability.

The full condition is a full-information **native manager**, not a behavioral oracle: it still misrouted 3/15 robust audits. No out-of-band belief probe was recorded, so this cell establishes behavioral routing and trace evidence but not the stated-versus-acted detection split. Legacy native reward was much noisier than `R_check` and is disabled in future runs.

This observed mechanism is consistent with several external findings that motivate, but do not substitute for, the planned causal tests:

- LLM judges and monitors rely on surface completion proxies rather than verified state changes; Advani et al. (ICML-FAGEN 2026) report no judge above AUROC 0.65 for false-success detection and anti-correlation with truth when comparing false success against honest failure.
- Outcome success is not equivalent to reliable execution: Cao et al.'s PAE (2026) finds that 27–78% of benchmark successes are procedurally corrupt yet invisible to outcome-only metrics.
- Bandyopadhyay (2026) reports that LLM evaluation attends to context 3–5 times less than generation and gives little attention to the candidate answer, offering a possible attention-level explanation for artifact under-reading.
- Literal or stated theory of mind need not yield functional adaptation; Riemer et al. warn that deployment decisions based only on stated understanding can be misleading. This motivates separate stated-belief and behavioral-action detection measures.
- The ICRL-AHT benchmark (2026) reports flat implicit-adaptation curves for purpose-trained sequence models even with ground-truth teammate actions. The present experiment tests whether semantically legible text changes that result for LLM managers.
- Masters et al. (2025) show that managers are not trivially effective: a non-adaptive Assign-All baseline can beat a chain-of-thought manager, and managerial intervention can be detrimental.

These precedents support the mechanism interpretation but do not establish causal mediation; a later completion-quarantine ablation must test that claim. Arm 2 intentionally does not encode it.

Interpretation: the primary toolset characterization cell passes and is frozen. Phase 2 now requires a budget-clean Arm-1P/Arm-2 comparison with identical shadow probes before a powered Arm-2 null can be claimed. A second perturbation and multiple workflows remain required before broad claims.

## 12. Phase-2 method: evidence-grounded temporal teammate belief

Phase 2 is a staged representation ladder, not a single precommitted system. Each arm must add one identifiable property while consuming only native silent observations.

**Zero-information constraint (linchpin):** every aid is computed exclusively from observations already available to the native silent manager. Formally, `z_t = f(o_1, ..., o_t; xi)`, with internal randomness `xi` independent of hidden state. An aid may select, compress, atomize, organize, or temporally weight that history, but may not consume grader truth, tool-call traces, perturbation schedules or labels, hidden prompts, private model/tool configuration, offline judgments, or any newly instrumented signal. A gain therefore targets computation/attention/representation; it cannot close irreducible missing information.

### 12.1 Arm 2: dimension-free atomic evidence ledger

Arm 2 is deliberately weaker and more general than the previously proposed dimensioned compiler. It is an append-only JSON ledger of atomic, source-grounded facts:

```json
{
  "evidence_id": "e7",
  "first_observed_timestep": 10,
  "worker": "portfolio_analyst",
  "task": "Batch A Robust Audit",
  "fact": "metric: 59",
  "source_pointer": "a548b05d-8dc9-4dae-beb5-50b2b2223d16"
}
```

Its schema contains **no** `dimension`, `polarity`, `strength`, `confidence`, verification tier, expected-versus-observed comparison, competence label, change hypothesis, causal explanation, or recommendation. It neither privileges method evidence nor encodes the current toolset perturbation. If an artifact explicitly states a procedure, that statement may appear as an ordinary fact; the compiler must not compare it with an expected method or interpret what it means. Task requirements remain in the native observation but Arm 2 does not manufacture a compliance judgment from them.

Arm 2 now uses a frozen deterministic enumerator, not an LLM selector. On every change to the full manager-visible workflow summary or message window, it appends completed/failed task status, each worker-resource description and visible content-preview line, and each new worker-message preview. It excludes task requirements, budget/progress, manager/stakeholder behavior, resource statistics, and inferred comparisons or absences. A visible assignment may only attribute a fact to a worker. Every eligible candidate is appended verbatim, with no ranking, classifier, or eight-fact cap; duplicates are removed by exact source/fact/attribution. Internally these remain immutable atoms for recall and relation grounding; manager-facing `task-bundles-v1` groups them losslessly by worker/task and source while preserving every evidence ID, timestep, source pointer, and verbatim fact. The identical projection prefixes Arm 2 and every Arm 3 variant. The versioned extraction and rendering specifications/hashes, complete candidate list, duplicate count, and empty omitted set are traced.

This deliberately exposes an **absence-evidence blind spot**: a verbatim enumerator cannot state that an expected event stopped occurring. Absence detection is an Arm-3 property requiring an explicit expectation and temporal comparison; it must not be credited to Arm 2.

This makes the representation contrasts precise:

- **Arm 1:** lossy narrative compression and salience.
- **Arm 1P:** the same narrative representation with persistence.
- **Arm 2:** persistent atomization, explicit provenance, and source-grounding—without evaluation.

Arm 2 does **not** yet solve completion-as-competence by construction. Completion and any other artifact fact coexist without weights, and the manager may still overweight completion. That is intentional: an Arm-2 gain would show that sourced atomic memory is sufficient; a null result would motivate the stronger interpretive/temporal machinery in Arm 3 without pretending Arm 2 already contained it.

**Hardened seed-101 result (mechanism smoke, not a powered estimate):** `atomic-lines-v2` produced 76 unique entries with zero omissions/failures and recalled all nine frozen change-relevant labels at zero delay. Nevertheless, `R_check=0.7317` remained exactly equal to native and Arm 1, and the semantic routing vector was invariant: every robust audit went to the degraded worker (the literal timesteps differed across 23/25/26-action trajectories). Batch A was assigned before contradictory evidence existed; after its z-score method/count became visible, the manager still routed robust audits B and C to that worker (`corrective routing=0/2`) while reasoning from the stale declared percentile profile. This rules out ledger-boundary recall failure for the labeled facts in this seed and points to attention/accessibility, interpretation/weighting, or belief-to-action binding. It does not yet rule out accessibility: Arm 2's mean prompt was 32.0k bytes versus 25.4k for Arm 1 (26.2% larger), failing the budget gate.

**Named finding—common-mode consistency blindness:** degradation made the nominal robust branch fall back to the screening branch's native z-score method. Their outputs therefore agreed at zero difference, so downstream consistency became exonerating rather than diagnostic; all three reconciliation tasks scored zero against the intended percentile-versus-z-score differences. In this environment this is structural, not a grading bug. Silent evidence can therefore be misleading rather than merely sparse. Core Arm 3 consequently excludes broad DAG/cross-task artifact comparisons rather than trying to infer independence from mostly non-comparable pairs. Downstream consistency remains an offline environment finding and may return only as a separately ablated channel with an explicit shared-referent and independence contract. The cross-domain prediction—that capability degradation often converges toward simpler common methods and thereby correlates branch failures—must still be tested rather than asserted as general fact.

### 12.2 Later belief layers (not Arm 2)

Arm 3 is specified as three treatments: Arm 3I-noQ adds profile–scope and direct requirement–own-method relations while deliberately allowing completion to support task fit; Arm 3I-Q changes only that coefficient so completion supports availability but not fit; Arm 3T retains quarantine and adds a deterministic evidence-event-weighted belief whose resting prior is the manager-visible declared profile. Task scopes are now call-free normalized visible-title families: only declared instance markers are removed, so A/B/C repetitions share a scope while distinct titles remain separate. For the primary capability cell, a frozen deterministic comparator sees only exact task clauses and the primary value of explicit artifact `method:` claims. It recognizes the two preregistered statistical procedure families—percentile/quantile and z-score/mean-plus-SD—and returns `compatible`, `incompatible`, or `insufficient`; unknown procedures remain insufficient rather than guessed. Parenthetical goal labels cannot relabel the primary method. Metrics, details, completion, history, and cross-task artifacts remain excluded. Repeated direct relations are accumulated deterministically rather than reinterpreted by an LLM history pass. This comparator is explicitly a stable instrument for the current capability lever, not the general behavioral-change solution; other evidence channels require separate ablations. The signed effect of Arm 3I-noQ is explicitly ambiguous: if it underperforms Arm 2 while Arm 3I-Q improves, the finding is that interpretation helps only when completion is quarantined. Arm 3T's mixed-polarity mechanics are tested locally with frozen synthetic accepted-relation sequences; empirical temporal-weighting claims are deferred until a natural mixed-polarity cell exists. Relation labels, completion quarantine, scalar beliefs, and temporal updates remain prohibited from Arm 2.

Manager-facing Arm-3 output is a compact deterministic state table appended after the unchanged Arm-2 task-bundle projection, not extractor prose. A fixed legend separates `execution_completions`, unverified `declared_fit`, relation-grounded `observed_fit`, and the arm-specific combined score/category, preventing a profile prior from looking like demonstrated competence. A unique scope activates only when a mapped task is ready/running or a substantive mapped worker artifact becomes visible; completion status alone does not activate it. Activation then persists. Only activated scopes are rendered, with all visible workers in stable order so alternatives remain comparable. Free-text extractor statements, task descriptions, artifact prose, hidden diagnoses, and recommendations are never rendered in this block. Relation requests are deterministically batched only by activated scope (all worker-profile packets) or by one direct own-requirement/method comparison per artifact arrival. Missing, extra, or duplicate packet results invalidate the batch.

The first seed-101 semantic replay (2026-07-21) was correctly stopped by the development gate: fact recall was 100%, but scope accuracy was 15/16, diagnostic contradiction recall was 1/3, and five generation failures invalidated the arm. Batch A/B explicitly reported mean-plus-two-SD against percentile requirements yet were misclassified as supportive; superficially adequate task-specific scope labels also fragmented repeated A/B/C work. A lever-agnostic refinement added canonical scope reuse, explicit requirement–artifact precedence over completion-like cues, exact packet/relation mappings, scope-family scoring, and persistent failure details. Its clean v2 replay also failed: it correctly unified A/B/C robust, rapid-screen, and reconciliation scopes, but over-merged portfolio/risk calibration and prioritization/reconciliation; diagnostic contradiction recall fell to 0/3; five relation batches failed because trace-only statements exceeded the 240-character schema cap. Version 1.6 removed free-text relation statements, supplied exact visible task exemplars for scope reuse, required one cited structured comparison per requirement-artifact evidence atom, and computed stance deterministically with conflict precedence. The clean v3 replay eliminated generation failures and recovered A/C contradictions at zero delay (`2/3` recall), while preserving the repeated robust/rapid/reconciliation families and separating prioritization. It still missed Batch B because the model paired its `method:` atom only with a generic reporting-format clause, misclassified some numeric/output atoms against procedure clauses, and over-merged portfolio/risk calibration. Version 1.7 extracted an exact cited task-constraint ledger and recovered all A/B/C contradictions at zero delay with 100% constraint and diagnostic-pair recall/precision and zero generation failures. Its v4 replay nevertheless failed the full gate: scope accuracy was 13/16 because all calibration families merged, and atom-level judgments produced false contradictions when one field did not independently satisfy a compound or separate sub-requirement. The failure remains localized to the semantic boundary rather than memory, batching, stance weighting, or schema reliability. These are development-only extractor calibrations, not Arm-3 reward evidence. Do not live-wire or run confirmatory Arm 3 until the offline gates pass.

A later semantic layer may propose falsifiable hypotheses about what a behavioral change means for assignment. It must read only prior information-preserving representations, cite evidence IDs, state alternatives, and remain separable from deterministic scoring. This is where capability-specific interpretation belongs—if it proves necessary—not in the general ledger.

Freeze the representation/controller boundary: an aid may state evidence-derived state and relations (for example, “audits e14/e15 report z-score; this task requests percentile”), but may not recommend or imply an action (“verify,” “reassign,” or “avoid W2”). Recommendations are a separate controller/nudge ablation. Comparable belief arms use the same fixed prompt location; changing placement is itself an explicit ablation.

Admissible future evidence channels include verifiable artifact claims, provenance statements, precision/formatting drift, downstream disagreement, self-baseline drift, task-conditional patterns, and realistic execution metadata. Core Arm 3 currently admits only profile priors and direct own-requirement/explicit-method comparisons; history and downstream/cross-task evidence require separate channel ablations. No channel is assumed to exist across both change levers. In particular, model+prompt change may yield omissions, factual inconsistency, instruction-following drift, or interaction changes without any method statement; the current narrow comparator is therefore a primary capability-cell instrument, not yet the general behavioral-change solution.

Active probing remains Phase 3 because probe/audit actions purchase new evidence and break the passive information-preservation comparison. Tool-call traces remain offline mechanism evidence unless platform-visible provenance is explicitly made part of every compared observation.

There is precedent for making beliefs and verification structure explicit rather than relying on raw-history inference alone:

- Li et al. (EMNLP 2023) find that explicit textual belief states improve both task performance and theory-of-mind accuracy in LLM teams.
- LLMCoordination ablations report Hanabi coordination dropping from 13.3 to 10.3 and then 4.3 as explicit theory-of-mind and verification reasoning steps are removed.
- Chang's RCA work (2026) reports that external process structure eliminates measured sycophancy (7–9% to 0%) where self-critique only reduces it.
- PAE finds integrity orthogonal to utility, efficiency, and interaction, motivating later multi-signal belief tests rather than a single success score.

These results motivate the representation, but do not determine its updater or prove that it will transfer to this setting.

## 13. Method baselines, ablations, and metrics

### 13.1 Anti-collapse ablation ladder

Run the staged arms at matched token budgets and horizons where context length is not binding. Each arm adds one declared property:

| Arm | Adds | Tests |
|---|---|---|
| 0. Raw history/native | — | The pilot failure and static declared-profile baseline |
| 1. Generic free-form summary | Compression | Whether any summarization/context engineering is sufficient |
| 1P. Append-only summary log | Persistence only | Whether an Arm-2 benefit is memory rather than atomization |
| 2. Atomic evidence ledger | Persistent atomization + provenance | Whether source-grounded factual memory beats salience-based summarization |
| 3. Interpreted temporal belief | Evidence interpretation + temporal weighting | Whether explicit belief dynamics are required beyond factual memory |

Arm 0 retains the static declared worker profile, analogous to the offline capability maps in Task-Aware Delegation Cues.

Token matching is a ladder-wide validity rule, not a per-result judgment. `audit_arm2.py` reports realized manager-prompt text in UTF-8 bytes and whitespace-token counts. Pairwise claims require ±10% size at comparable decision points—especially immediately before post-evidence robust assignments—and must check mean plus late/max size; episode means alone can hide late ledger growth and are distorted by unequal 23/25/26-action trajectories. Any violation requires an explicit size-matched control. Context length must remain non-binding. The full ledger stays uncapped because silent fact selection would recreate the salience confound.

The predicted signature is an improvement at 1P→2 and possibly again at 2→3. Arm 1 versus 1P isolates persistence; Arm 1P versus Arm 2 isolates narrative memory versus atomization when budget-clean. If all improvement occurs at 0→1, the method has collapsed to generic context engineering; report that rather than relabeling it teammate belief. If powered, controlled Arm 2 is null but Arm 3 improves, interpretation/temporal weighting was load-bearing.

Selective mechanistic prediction: `P(suspicion decreases | completion)` may remain high through Arm 2 because the atomic ledger does not label or weight facts; it should fall only when Arm 3 explicitly separates completion from contradictory evidence. Benefit should grow with change-to-decision distance, distractor volume, and worker count, and shrink toward zero under full observability.

Within Arm 3, separately ablate interpretation, completion quarantine, numeric update rule (standard no-decay product posterior, additive/sum-posterior HBA, exponential decay, and changepoint/CUSUM), semantic diagnosis, and prose versus JSON rendering. Keep the full-information oracle, partial signal, no-change control, noisy-but-unchanged control, and naive/frozen floor as references.

### 13.2 Strong comparison arms

- **Monitor agent:** a second unconstrained LLM watches traces. This tests whether structured filtering beats unstructured extra inference compute — a direct "structure versus scale" contrast.
- **Trained lightweight detector:** TF-IDF/XGBoost or an equivalently strong artifact classifier, motivated by Advani et al.'s reported 0.83–0.95 AUROC. Use it as the trained changepoint-detector baseline rather than a strawman.
- **Environment-side dual control:** add explicit DAG verification nodes in a separate condition, with diverse methods and—where feasible—different data/provenance/model-tool paths so the branches do not share the same likely failure mode. Method diversity is necessary but not sufficient. This changes the environment dynamics/information path and must be framed as infrastructure-side verification versus agent-side estimation, not as an information-preserving Phase-2 arm.
- **Active probing:** reserve for Phase 3; it intentionally purchases new observations.
- **Fine-tuned manager:** out of scope for the current thesis, which evaluates a frozen manager policy.

These alternatives occupy different scientific corners: some add information, some require labeled training data, and the monitor adds unstructured inference compute. The layered estimator is the agent-side, training-free, information-preserving method under test; the comparisons establish which constraint matters rather than assuming it wins.

Measure `R_check`, oracle-gap closure, post-evidence gap closure, first informative evidence, stated and behavioral detection latency, incorrect work before/after detection, retries/reassignments/probes, added tasks, token/timestep cost, and false-positive rerouting under no-change control. Also report the robust-audit routing vector with an evidence-opportunity mask: assignments made before any informative artifact are irreducible signal delay, while later assignments test correction (seed 101: A pre-evidence; B/C post-evidence; `0/2` corrected). Compare semantic assignment mappings rather than literal timesteps, since arm trajectories differ in length. Paired seeds and workflows remain mandatory.

Report evidence recall and delay by labeled channel. Offline only, annotate evidence **relations**—not necessarily isolated atoms—as `diagnostic`, `exonerating`, `neutral`, or `ambiguous` under a frozen codebook; these labels never enter Arms 0–2. Reward remains an episode-level outcome; attribute reward to a channel only through a controlled channel-removal ablation, not post-hoc correlation. Evidence being available does not establish that it caused the manager's decision.

## 14. Scope discipline and next gates

The architecture is an **instrument, not the contribution**. The contribution is a sequence of falsifiable claims, each isolated by a dedicated contrast:

1. The observability gap exists → full/partial/silent `O` conditions.
2. An avoidable part is computational rather than informational → strict information preservation.
3. Completion-as-competence drives the failure → a later explicit completion-quarantine contrast, not Arm 2.
4. Whether persistent source-grounded facts beat summarization → budget-clean Arm 1P versus dimension-free Arm 2.
5. Temporal weighting matters → deterministic update-rule ablation.
6. Semantic interpretation is load-bearing for re-orchestration → Tier 1+2 versus Tier 1+2+3.

Any component that does not isolate one of these claims should be cut. Build sequentially: first the dimension-free JSON ledger, then only the minimum interpretation/updater needed for the next contrast. The writeup posture is **a minimal belief estimator whose every property is ablated**, used to probe Phase 1's failure—not a novel framework.

### 14.1 Current scope and upgrade paths

The current scope characterizes a frozen pretrained manager and tests the minimal information-preserving estimator. After the deterministic Phase-2 result is established, include the cheapest ML upgrade: fit Tier-2 parameters or replace the updater with a lightweight learned detector on labeled change episodes, then measure cross-perturbation and cross-workflow generalization. Keep it visibly separate from the training-free arm so it cannot blur the core causal claim.

Reserve **environmental active probing** for Phase 3 or a second paper. Probe/audit/verify actions create a value-of-information POMDP; a small policy over `{probe, trust, reassign}` conditioned on the belief can then be compared with zero-shot LLM probing. This deliberately breaks information preservation and is distinct from the non-intervening shadow belief probes used only for measurement in Phase 2.

An optional formal extension is to bound value differences between observation conditions information-theoretically and express the digest as targeting the policy-suboptimality term in a regret decomposition.

Venue posture: the current characterization plus ablated estimator fits agents venues or ML workshops; the learned cross-perturbation module strengthens the ML contribution; the active-sensing policy is the substantive RL extension. Do not inflate the architecture to chase a venue before the six claims above are resolved.
